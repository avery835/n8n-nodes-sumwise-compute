## Review the actual CI package before dispatch

CI installs the lockfile, builds, runs lint/tests and package/source checks, then creates one npm tarball with lifecycle scripts disabled. Successful main pushes retain **npm-<full-public-SHA>-<run-attempt>** for seven days, containing the tarball and **manifest.json**. The manifest records source SHA, run identity, package/version, tarball SHA-256 and SHA-512 integrity, tooling versions and the selected file hashes. The GitHub artifact archive digest is distinct from the npm tarball digest inside it.

Before any publishing dispatch, independently download and inspect the artifact from a completed successful **CI** run for the intended repository, **push** event, **main** branch and exact public SHA. Require all gates and the artifact step to have succeeded. Check its actual tarball entries/content against the reviewed package selection, notices, public metadata, source/build files and manifest. Reject unsafe paths, links, unexpected files or secrets. Do not rely only on filenames, counts, a manifest's own claim or an older dry-run log.

Record the inspected npm tarball's 64-character lowercase SHA-256 as **reviewed_package_sha256**. The manual publish workflow builds and checks the same public SHA, packs once, and refuses publication unless its actual tarball bytes match that reviewed hash. It publishes that verified tarball, not an implicit fresh pack of the working directory. A hash mismatch requires investigation, not a bypass. Prepared YAML and a local package check do not assert that remote CI, artifact inspection or publication happened.

## Validation and verification limits

The stable credential test is a fixed, status-based Evaluate request; it does not validate the calculation result body. Typed exact integer 2 is a separate integration/service-smoke assertion. Each accepted test consumes request allowance, including tests triggered by credential save/open/retest. Authentication errors, limits and timeout do not prove that no allowance was consumed. Normal Evaluate continues to validate the closed response contract and preserve exact strings. No host-wide logging/retention guarantee follows from connector sanitization.

Prior bounded live credential, Evaluate, both reconciliation decisions and generated-wrapper calls passed through an authorized local route retaining the real HTTPS hostname and certificate validation. External TLS reachability was a separate observation, not a full external authenticated workflow. Expected revoked-credential rejection was observed in a later continuation; the original interrupted lifecycle remains stopped. Owner-reported editor checks are not a new automated walkthrough. No external model/agent loop, customer integration or production-suitability conclusion follows.

The earlier preview's deprecated credential-helper/scanner finding is historical evidence, not an upstream waiver. Record the stable implementation's actual current lint/scanner results and any remaining findings. Passing local checks or choosing a stable/latest version does not establish Creator Portal acceptance or a verified-node listing. Creator Portal submission, reviewer service access and Cloud claims require their own authorization.
